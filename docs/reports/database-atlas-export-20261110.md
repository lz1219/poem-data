# 数据库驱动地图生成：隔离验证

2026-11-10，R-17。按项目持有人要求，以线上数据库为准；本次只读导出并在隔离目录生成地图，没有切换线上发布或删除数据。

现有 `export_json` 将数据库中的作品、人物和行迹导出为中间文件；`emit-atlas.mjs` 新增 `--data-dir`，可消费该导出，不再强制读取仓库 `data/`。路径缺失或三个目录任一为空时拒绝生成，默认调用保持兼容。中间文件是临时生成输入，不是第二套人工维护数据。

本地新版 Django 直接连接线上业务库导出失败：线上 `corpus_work.place_key` 列不存在，说明代码与数据库架构存在版本差异；不能因此直接运行迁移。改用线上当前运行容器的版本，以只读数据库连接导出到容器临时目录：69作品、39人物、20行迹；复制至本机隔离目录，用新参数生成三个地图文件，生成计数69作品、20地图人物、13条新建行迹及7组补站。尚未完成线上地图渲染、发布或全字段迁移验证。

与本地旧 JSON 逐文件比较：作品键69/69一致，但48篇字段不同（系年48、状态48、文本对象34）；人物数据库39、本地35，行迹20均存在且1条不同。对象差异并不均等于正文差异，也不自动判断正确性；当前按用户要求以线上数据库为准，切换前须检查差异对地图及证据状态的影响。保留当前线上库与原 JSON，未自动覆盖或删除。

使用方法：在与数据库架构匹配的环境中将 `manage.py export_json --out <临时目录>` 导出，然后 `node scripts/emit-atlas.mjs --data-dir <临时目录> --target <隔离地图目录>`。现有导出涉及研究记录及私有目录，正式流水线须限定输出路径、只读事务和完整性检查；不能把临时验证称为迁移完成。
