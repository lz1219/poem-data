# 江山行止 · 编纂与学术质量规范

> 适用于整个项目的原文、译注、赏析、评点、背景、人物、行迹和研究记录。与[项目总纲](project-charter.md)共同构成后续编纂依据。
> 本文为采纳的目标规范。历史内容按批次迁移，在核查完成前保留实际状态；本次文档制定不代表数据、界面和校验器已经全部符合新规范。

## 1. 共同准入规则

每一项内容明确所属对象和范围、所据来源、生成方式与审校状态。外部事实应有可定位材料；本站语境释义和解释说明依据哪些原句；推断单独标明推理与边界。来源链接或校验通过只能证明相应检查结果，不能替整段解释背书。

来源记录区分古籍原作、具体版本、电子转录、影像和资料提供平台。记录版本题名、编校者、卷篇或叶页、稳定地址与版本标识；GitHub 固定提交与文件路径，维基类固定修订，原件保存哈希。完整原件的取得、存储及公开再分发条件分别核验；权限不清的先保留目录和链接。

镜像、分支与同底本转载归入同一来源链。主张两个独立来源时，说明独立在哪里；不能仅按两个网址计数。OCR、机器匹配和搜索摘要用于发现线索，核对原件后才形成定位证据。

## 2. 栏目分工

| 栏目 | 必须完成的工作 | 必须交代的边界 |
|---|---|---|
| 原文 | 忠实呈现选定版本，标出处与文本边界 | 全文、摘录、残篇；繁简转换与反推；标点来源；异文及缺字 |
| 大意／导读 | 简洁说明内容与结构，帮助进入作品 | 与逐句译文区分；避免混入未经说明的史实和作者意图判断 |
| 译文 | 按原文句段对应，现代汉语忠实通顺 | 省略补足与有争议的读法可解释；摘录只译所收内容 |
| 注释 | 解决具体阅读障碍，指出词义、句法、典故与语境 | 区分字书义、古注、本站拟释、异说及待核项 |
| 本站赏析 | 以具体字句、结构和上下文支撑解释 | 文本分析、审美判断、历史事实、作者意图推测分别说明 |
| 历代评点 | 呈现可核的古人原话 | 评者、时代、原文、书名与卷页齐全；转引与原典区分 |
| 背景与系年 | 交代理解作品所需的史事、时地与依据 | 作年与所述之年分开；确知、约年、区间、异说、未知分别表达 |
| 人物与行迹 | 建立有据的身份、时间、地点、事由联系 | 籍贯、出生地、任所、行旅、作品所写地与推测地点区分 |
| 研究推测 | 提出可检查的假说，说明推理、反证与替代解释 | 明确生成与审校方式；不混入确定事实和默认路线 |

## 3. 原文与版本

默认公共阅读优先采用来源可追溯、范围清楚的已有标点文本和简体阅读副本；需要对读的版本可并列；原库的旧原录可按[现行整理规则](corpus-operations.md)替换，不强制全部留在正式库。选本同时比较版本身份与原件可核性、文本范围和完整度、校勘信息，以及与研究对象的关系，不让难读的原版排印成为公众阅读的唯一入口。年代早、传播广或下载方便都不能单独决定优先级。由项目持有人或其授权责任编辑记录选本理由与未决问题；AI可以提出候选，不能代署人工定案。

尚未定案时可以保留现有基线或提供临时阅读本，显著标为版本待核。原PostgreSQL阅读本更换来源可以在操作备份和注明出处后直接替换，不强制保留旧全文；核对卷篇、已有引用及译文、注释、校记的对应关系。已公开的编纂研究修订仍保留引用与修订说明，不把全文库清理等同于删除研究历史。未重新核对的旧译注不能继承原来的已审状态。

选定底本后按其文本逐字保存，不手抄重构，不将不同版本拼成未说明的“通行本”。需要保留的版本分别记录，校改另记底本读法、异文、依据和取舍；异体字与实质异文分开处理。

标点记录版本或整理来源。无标点文本保留其状态，不能自行加标点后伪称原版已有。将来的辅助断句若另行建设，须作为独立编辑层呈现，不能混入来源正文。

繁简转换保留转换器和对应关系；反推繁体不能标为原始底本。只有核对了相应正文范围，才能改变其来源状态。机器片段命中不证明整篇同本、全文完整或系年正确。

摘录标出所收范围及省略情况，翻译与赏析围绕该范围展开。摘录多段时逐段定位，不能让拼接段落被读成原作连续段落。

## 4. 译文与注释

首期已确认决定见[AI阅读细则](ai-reading-policy.md)：按自然段整理，选句展示所属段落译文与相关注释；忠实完整的现代汉语主译配重要异说及取舍。原文默认简体、可切换来源原字，注释绑定原字定位。首批为《资治通鉴》卷一；重点清单安排赏析，普通段落优先译注。

译文使用独立内容字段，不把旧大意直接改名。对应原文段落的标识与次序应可检查；原文修订后检查译文和注释是否仍对应。原译对照不能凭相同段数就断言语义已经核定。

译文忠实传达原句，必要的省略补足根据语法和语境作出；会影响理解的补足写进注释。有重要歧义时说明采用的解释及替代读法。历史背景、赏析判断和作者心理不暗中补进译文。

重要分歧的最低收录口径：会改变句意、人物指称、事件关系或主要赏析结论的读法须交代；其余异说按实际阅读障碍和专题需要取舍。不能罗列没有文本或文献依据的任意可能，也不能用“非主流”代替论证而排除有据异说。

注释按阅读障碍组织，覆盖古今异义、虚词句法、典故、制度、地名、专名、异体和异文等实际需要。每条至少有被注词句、原文定位、语境解释和依据；采用古注或字书时指明具体条目或卷页。本站拟释明确其性质，依据不足则待核。

注释验收检查关键难点是否得到解释、译文采用的读法是否可查、解释是否超出证据；不设最低注数。通俗措辞保持准确，专业问题允许展开古注、异说和例证，避免只给同义词或堆砌资料。

## 5. 赏析、背景与评点

赏析可以有鲜明判断，但须从字句、句法、意象组织、视角、声音或篇章结构提出论证，说明这些证据怎样支持判断。分节由作品问题决定，不机械套用同一模板，不以固定字数替代解释深度。

文本人物与历史作者、作品场景与实际行迹、阅读解释与作者意图保持区分。涉及身世、政治处境、创作动机和因果关系时补史料，并说明推断环节。存在合理异说时交代分歧及本站取舍；无出处的“通行说”“学界认为”不得充当依据。

背景只陈述有据且有助理解的内容。作品表现少年、壮年、老年，并不自动构成作者可据以定年的自传；未经确认的文学场景不写成实际驻留地点。

历代评点以评者可考、原文可核、与作品相关为准，不以知名度或每篇配额作为准入条件。原文、评者、时代、书名和卷页不足的保留为研究线索；AI 自撰或转述不能放进古人原话。本站对评点的解释与评点原文分开署明。

## 6. 生成方式、审校与 AI

译文、注释、大意、背景和赏析均记录生成方式，适用于单项内容而不仅是推测区。本站署名表示发布责任；首期批量AI译注统一标为“AI生成·未经人工审校”；明确处于起草阶段的内容可标“AI起草·未经人工审校”。人工完成相应审校后标明范围、审校人和时间，并保留 AI 参与记录。历史生成方式未知时如实说明。

AI 参与标识始终在对应内容旁可见。审校后可显示“AI起草·已人工审校（具体范围）”；人机共同编写则按实际情况标“AI参与”。只审部分段落或注释时分别标示范围，未审部分继续显示待审，不能用局部审校覆盖整项内容。

AI 记录模型、版本可得性、生成时间和方法；环境未提供精确快照时注明缺失，不编造版本，也不承诺完整复现。AI 辅助检索、提取、草拟与推理分别记录；AI 自检、双模型复核都属于机器检查。

公开 AI 推测须有可核原句，展示推理、反证检索情况及替代解释。按实际状态显著标注“AI推测·未经人工审校”或“AI推测·已人工审校（具体范围）”，审校后仍保留推测属性；审校本身不等于采信为事实。尚未检出反证不等于不存在反证。无据猜想仅作内部线索；待审推测不进入确定事实索引、默认年表或地图路线。

“具名人工审校”要求可追踪的真实审校者，说明核了哪些来源、哪些内容及作出什么决定。未安排人工审校时允许发布合格的待审内容，但必须符合对应栏目准入条件并保留待审标识，不能凭人工点击或具名登记即获得“已核”标识。

## 7. 核查状态与引用

底本核对、引文定位、译注审校、文学解释审校、系年与行迹核验分别表达其范围。展示时保留不同检查结论；字段存在不等于内容完成，已核正文不等于已核作年。

沿用的 pending / partial / verified / restricted / rejected 分别表示待核、部分核实、已核指定事项、来源受限、已否决。verified 必须有相应证据与具名核验决定；不能扩张成整篇解释已获学界认可。文学解释记录采用、保留异说或不采纳的理由，避免用单一真假标签代替讨论。

条目总览的“部分核实”表达仍有承诺范围未完成；具体事项的“已核”必须带范围。例如“正文·已核某版本”“译文·AI起草待审”“系年·待核”可以同时存在，此时总览仍为部分核实。总览优先表达核查覆盖情况，禁止用不带范围的“整篇已核”替代这些事项状态。

记录有稳定标识与修订号，引用包含版本定位、所引修订和链接。公开旧修订保留；新证据推动新修订与勘误，不改写旧引用。内部转公开沿用修订序列，内部历史继续隔离；撤回公开内容用有说明的新修订退出默认展示。

公开待审译注、部分核实内容及 AI 推测可以作为相应解释或研究对象引用，须保留状态和限定。引用某项观点不等于把它当作已核历史事实；用作事实依据时还须回查其原始材料。教学讲义与研究导出同样保留这一边界。

## 8. 工作流程与验收

首期AI译注在整理阶段批量生成、检查并入库；网站读取已有内容，缺项显示“译注待补”。符合来源、定位、生成标识及检查要求的未人工审校内容，可进入可公开批次并提供纠错入口；程序检查不等于语义确证或人工审校，也不绕过下述发布确认。具体检查与原文变更处理见[AI阅读细则](ai-reading-policy.md)。

发布审查检查内容是否适合以当前状态对外提供，与人工学术审校分开：最低检查文本边界、来源与使用条件、引用定位、生成及待核标识、内部资料隔离、推测与事实区分，以及本批相关的结构、往返、生成和阅读验证。由维护者记录批次、检查结果和已知缺口，项目持有人或其授权发布维护者依现有发布纪律确认发布。AI可准备候选批次与检查材料，不能代署授权者的发布确认或人工学术审校。

发布审查通过表示允许按所标状态公开，不表示内容已获学术核定。没有人工学术审校的合格内容可保留待审标签发布；出处不足、使用条件未核或涉及内部资料的内容须依对应规则限制公开范围。

1. 确定专题对象、版本与收录边界，登记已查与受阻来源。
2. 保存原件与来源元数据，核对正文及引文定位，记录异文和缺失。
3. 编写大意、逐段译文、定位注释、背景和赏析，逐项附依据；推测另列。
4. 做结构校验、原译对应检查、机器引文匹配和 AI/内部记录隔离检查，保留机器检查性质。
5. 按具名人工审校的实际范围登记决定；尚未审校的合格内容保持待审。
6. 从发布 JSON 同步数据库与两站，核对原文、摘录/来源/AI标识、引用链接、研究展开和地图行为。
7. 本地验收与提交，按批次列入待发布；发布遵守项目确认流程。

完整条目的阅读层验收包括：读者能看懂原句、找到疑难解释、区分解释与史实，并能沿来源复查。研究层验收包括：版本、定位、证据、反证与修订能够连贯追踪。已承诺范围存在缺项时明确标示，不用空白栏目制造“内容已齐”的印象。

## 9. 历史数据迁移

先清点无据断言、错误版本归属、译注缺失和混写的推测，记录真实状态。内容重写保留旧修订，不自动清除反推与待核标记。现有大意继续作为大意，待逐段译文具备后才显示译文栏目。

通用数据契约与往返先落实，按2026-11-04确认顺序先用《资治通鉴》卷一验证段落译注及重点赏析，再扩展诗、词和文章摘录等样板与两站应用。样板通过后按专题分批提升；未迁移的条目持续显示其实际质量状态。标准变更记版本、理由和迁移范围，不能把后来的标准倒签为历史内容已经满足。
