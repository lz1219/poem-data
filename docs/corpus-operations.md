# 原库整理的当前执行规则

2026-11-02，项目持有人明确调整：优先采用《传习录》《清史稿》及维基《旧唐书》这类可读文本；合适的新源可以替换旧源，不要求在正式库长期并存全部旧原录。本文适用于原PostgreSQL全文语料库，优先于旧补库规格中的强制保留要求。精选读本、地图上游保护及发布确认流程不因本次调整自动改变。

## 数据库工作位置

2026-11-09：项目持有人要求不再维护本地 SQLite。后续实际数据整理、核对和入库以服务器现有 PostgreSQL 为准，不再同步本地 SQLite；连接信息使用受保护环境，不写入仓库。JSON 仍按项目现有发布流程维护，数据库变更前核对目标并按需备份。测试使用隔离数据库或临时环境，不对线上业务数据运行测试、初始化或清空导入。本地 SQLite 文件暂不删除；Django 未配置连接时的既有 SQLite 回退尚未改动，不代表它是工作数据源。

`node scripts/check.mjs` 默认不检查本地 SQLite，会明确显示数据库往返跳过；需检查指定数据库时，先配置 PostgreSQL `DATABASE_URL` 并设置 `CHECK_DATABASE=1`；缺少连接或使用非 PostgreSQL 地址会报错，不会退回 SQLite。该检查是对指定数据库与 JSON 的比较，不代表已完成线上备份或数据审校。

## 统一文献库的新方向

2026-11-10 项目持有人明确要求以数据库为准，停止围绕精选 JSON 与语料库的重复正文逐条同步修补；统一作品、典籍与版本身份，重复内容在核对关联、引用及备份后按迁移批次撤出。现有 JSON 仍是地图生成输入及既有发布契约，在统一数据库与导出替代方案落地前尚不能称已取消；后续以数据库驱动生成物，切换前保护现有链接、译注和引用。

## 选源与替换

有标点、分段清楚、正文及注释可区分是公共阅读准入条件，同时检查卷目范围、缺字与来源。平台名称不能单独证明质量；不把研究原录直接当默认读本。保存来源链接、版本/修订及必要定位，不为保留旧原录制造重复馆藏。

2026-11-04补充：当整书修补成本高、合适新源能够覆盖原有内容时，可以整书重新整理并替换，不必保留旧正文作为正式馆藏。先对照目录、正文、校注和授权，检查段落及研究引用的迁移；未对应的引用不得静默删除或转为确证。先准备并读回受影响数据备份，在服务器暂存、校验后切换，并以书为单位复核结果。若没有质量和覆盖均合适的新源，继续保留现有内容，优先批量修复已核实的问题。

后续导入的默认阅读文本应有真实卷题、可辨的段落和来源已有标点；正文与来源编号、校记、古注和技术标记分别处理。简体转换标明方式并保留可定位的来源文字，不能用转换结果冒充原版。目录完整性、注释覆盖、文字质量和人工作业状态分别记录；无法可靠拆分时先作为待处理内容，不把混杂文本充作完成。

[中国哲学书电子化计划](https://ctext.org/zhs)用于检索、版本线索及人工核对。[站方说明](https://ctext.org/faq)禁止自动软件批量下载页面，转载受条件限制；[API](https://ctext.org/tools/api)亦有使用条件。未经逐项核定许可，不把其在线可读等同于可批量抓取和公开分发；可追溯上游并评估其他可用来源。

## 服务器执行与性能

已验证项目位于/opt/poem-data，poem-web和my-pg均使用host网络；现有Python环境可通过127.0.0.1连接原库。后续整理、暂存、备份、写入和校验优先在服务器完成。任务目录为/opt/corpus-data-jobs；项目挂载只读，不为运行整理任务修改网站部署。凭据仅使用现有受保护环境，不复制凭据文档上服务器。

服务器直连GitHub和维基各两次测试失败，不能承诺全部来源免传输。已有库内资料可直接处理；新源另选可达入口，必要时只传一次已准备好的压缩数据，禁止逐条跨公网入库。

[临时表实测](reports/server-local-execution-check.json)：相同1000条正文和来源，保留主键、唯一、外键和GIN索引，服务器32条一批为0.1181秒、512条为0.097秒；本地远程连接512条为3.577秒，见[本地测试](reports/copy-batch-benchmark.json)。这是阶段性微基准，不是正式全链路速度保证，临时表不反映全部WAL等成本。

- 下载、解析、字符转换、目录匹配和测试在事务外完成。
- 写入优先COPY或COPY到暂存表后集合更新。默认每条COPY最多512行或约1MB，单条大记录不截断；以真实耗时调整。
- 每批只在一个短事务完成必须同时生效的写入及必要检查。提交后单独只读核验；不在一个线上事务反复全量回读、撤回、重灌和回归测试。本批normalize_corpus已采用此流程，其他旧脚本尚未全部改造，不能冒称均已符合此规则。
- 用唯一约束防重复；更新自带的行锁优先。需要先检查再修改时只锁当前目标，事务级同批互斥仅防协作脚本重复执行。一般盘点不加FOR UPDATE，不在锁内网络下载或跑全库测试。
- 已有库的索引、外键、WAL及autovacuum不默认停用。先定位CPU、I/O、网络及锁等待；空表初始化与在线替换分开设计。不要照搬重建整库的优化到当前小批整理。
- 同机优先使用现有本地数据库连接或服务器文件COPY；只回传数量、耗时、错误和报告。无需为服务器文件COPY提升现有账号权限，可在同机用COPY FROM STDIN。

依据：[PostgreSQL批量装载](https://www.postgresql.org/docs/18/populate.html)、[COPY](https://www.postgresql.org/docs/18/sql-copy.html)、[锁](https://www.postgresql.org/docs/18/explicit-locking.html)。
